## The problem

I wanted a personal AI setup that runs day-to-day without babysitting: distinct
spaces for different parts of my life, memory that persists across sessions,
health data captured automatically, and old data cleaned up on its own.

## What it is now

Agento is a Hermes-based stack, not a Discord bot fleet. ONE multiplexed gateway
container serves three profiles: **god** (main — money tracking, cookbook, health),
**story** (a lore vault backed by a Git repo), and **resumes** (LaTeX resume
tailoring backed by this very repo). Each profile has its own workspace, skills,
and credential scope.

The frontend is **Agento**, a custom Android app (Jetpack Compose): God/Story/Resumes
chat tabs with threaded, on-device-persisted conversations, plus Tasks, Storage,
Reminders, and Settings. One Server URL + Password — the app talks to an nginx
proxy (`:8080`) that routes `/p/*` to the gateway's OpenAI-compatible chat API
(`:8642`) and `/api/*` to the health-sync service.

All three profiles reason through **OpenCode Go directly** (`mimo-v2.6-flash`),
with per-tab provider/model selection from the live gateway catalog. Domain
capabilities come from Go MCP servers I wrote — money, cookbook, health-check —
plus Playwright browser automation on every profile.

## How it runs

One Podman Compose file: gateway, health-api, proxy, and a one-shot retention
job. Health Connect syncs (steps, sleep, workouts) flow from the app through
health-api into per-day MongoDB docs. Every night at 03:00 the retention binary
prunes money transactions older than 90 days and health logs older than 30 days —
while weight and cookbook data are permanent, and the Git-backed profiles need no
DB retention at all. Dev checkouts point at a throwaway Atlas database, so
production data is never at risk. A `hermes.sh` CLI (`init|start|stop|status|clean`)
orchestrates the whole lifecycle, and every app change ships a versioned release
APK with in-app updates.

## What it taught me

Multiplexing beats multiplicity: one gateway process with three scoped profiles
is simpler to operate than a fleet of bots. And reliability is designed, not
hoped for — isolated credentials, automated pruning, and a single secret store
(the git-ignored `.env`) matter more than model choice. Most of this system
exists so that nothing pages me.
