## The problem

Object storage bills aren't dominated by bytes — they're dominated by requests.
A naive gallery pays S3 for every bursty upload, every re-read, every piece of
noise. I wanted an ingestion path that was fast under burst and cheap at rest.

## What I built

A tiered pipeline with one Docker Compose file. Uploads land in self-hosted
MinIO under uuid-hex names (the endpoint 503s unless both MinIO and Mongo are
up — no half-written state), with metadata in MongoDB. Reads resolve through a
chain: Redis first (55-minute TTL on signed URLs), MinIO presigned URL next,
S3 fallback last. At midnight a cron job mirrors curated files to S3 with
`mc mirror`, deletes the mirrored objects from MinIO, and invalidates their
Redis keys. A `/health` endpoint pings all four backing services and reports
degraded unless Mongo is healthy.

The result is fewer S3 request charges: noisy traffic never reaches S3, only
the nightly batch does, and repeat reads never leave Redis.

## What it taught me

Cost is an architecture constraint, not an invoice surprise. Batching the
expensive operation (S3 writes) into a nightly job and caching the expensive
read (signed URLs) is the entire design — everything else is plumbing. This is
the project that most shaped how I think about building cheap-to-run systems.
