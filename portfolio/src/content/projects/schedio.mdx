## How it works

Three roles, one codebase. Students upload projects, colleges see their own students' work with monthly charts, recruiters search everything with institute and domain filters.

Projects are code zips, video and photos. The zips land in GridFS; the backend unzips them server-side and shows a file tree where each source file gets a plain-English summary from `gemini-2.5-flash` — what the file does and which functions matter — so recruiters can skim unfamiliar stacks without opening an IDE. Descriptions go through a plagiarism service before submission. Likes, comments and recruiter bookmarks are in the same API. Auth is email plus bcrypt with Mongo-backed sessions — JWT is only used for the email-verification link. Password reset goes out through Gmail templates. It ships with Docker files and runs on Vercel.

## Scope

Three roles in one codebase, running live: student uploads with plain-English summaries on every source file, college views with monthly charts, and recruiter search with institute and domain filters.
