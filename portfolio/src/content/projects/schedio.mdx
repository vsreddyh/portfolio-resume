## The problem

Student projects are scattered across GitHub profiles nobody finds, and
recruiters have no good way to discover them through colleges. I wanted one
place where students, colleges, and recruiters meet around real work — with
the evaluation tooling recruiters actually need.

## What I built

Schedio serves three roles from one codebase: students upload and showcase
projects, colleges manage their students' work with monthly analytics, and
recruiters search across everything with institute and domain filters.
Auth is email + bcrypt with JWT and Mongo-backed sessions, and every route
is gated by user type.

The core loop is upload → explore → evaluate. Projects bundle code ZIPs,
videos, and images into GridFS; the backend unzips code server-side and serves
a file-tree viewer where each file gets its own Gemini explanation. Project
descriptions run through a plagiarism API, and engagement (likes, comments,
recruiter bookmarks) is first-class. Colleges get Chart.js monthly and
domain analytics; profiles are print-friendly for handouts. Password reset
flows through Gmail templates, and the whole thing ships in Docker
(dev + prod Dockerfiles) with the live deployment on Vercel.

## What it taught me

Marketplaces die of emptiness, not bad UI — so the evaluation tooling
(plagiarism checks, per-file code explanations, analytics) is what makes the
platform useful to recruiters rather than just a prettier project list.
And boring auth choices (sessions in Mongo, short-lived reset tokens) pay off
when three user types share one API.
