## The problem

Devotional apps shouldn't need accounts, backends, or connectivity. A daily
verse reader is the perfect offline-first app: the entire corpus fits in a few
megabytes, so ship the database with the app and never phone home.

## What exists (in development)

Scrapy spiders crawl English, Hindi, and Telugu verse pages into a trilingual
CSV, compiled into a SQLite database (701 rows) bundled as a 2.8 MB app asset and
read through `SQLiteProvider` — zero network calls. Around it: a drawer shell via
expo-router, Settings, Terms and Privacy screens.

## Honest status

UI prototype. The dataset and bundling are done; the reading loop is not. The
home screen renders placeholder text, `getVerse()` ignores its arguments and
returns the first row, the language picker is `useState` that is never persisted,
and the history table has no writer. The scraped data also needs a cleanup pass:
701 rows contain only ~590 distinct chapter/verse pairs, so duplicates are still
in the bundle.

The data pipeline was the hard part and it's finished — the app around it is what's
left.
